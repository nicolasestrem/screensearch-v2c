# ScreenSearch V2c — 0.3.0 Roadmap: Subtraction + Flow Recall + Open Surface

> **Repo destination:** `docs/0.3.0.md` (sibling of `docs/0.2.0.md`).
> **Arc name:** **P7 — Surface reduction + flow recall + local API.**
> **Operating model:** identical to the 0.2.x arc — every PR follows
> `specs/04_CLAUDE_CODE_BUILD_PROMPT.md` (mandatory reading order, stop-at-ambiguity,
> verbatim verification, build-loop outputs `05`–`08`), and **recycles `specs/04` as the
> per-PR operating prompt**. PR1 extends `specs/04` to cover this arc.

## Why

Two forces drive 0.3.0, and they pull in the same direction.

**1. The product has more surface than a solo project can carry.** 0.1.0 + the 0.2.x arc
shipped a real app — but also six event-capture triggers (two of which ride a global
`WH_MOUSE_LL` mouse hook the 0.2.0 roadmap itself deliberately steered away from), three
model tiers per inference lane (one of which, Nemotron, is the only non-Apache license and
the only unproven hybrid arch in the tree), and a dark, flag-off image-embedding lane
(`enrich.image_embeddings`, nomic-embed-vision) that carries a second vec0 table, a second
model download path, and a job kind — all untested in practice because nobody turns it on.
Every one of these is config surface for users, decision surface for the maintainer, and
audit surface for the privacy-conscious audience this app is for. 0.3.0 **removes** them.

**2. Recall is still friction-gated, and the app is a silo.** Today, recalling something
means switching to ScreenSearch — a context switch to recover from a context switch. The
market signal since Rewind's shutdown is consistent: people praise *instant, zero-friction
search*, and the open-source audience explicitly wants *an API to build on* (the loudest
criticism of Windows Recall is "no API, no automations"). And for the maintainer's own use
case (ADHD): the killer feature isn't a report at day's end — it's answering **"what was I
doing 20 minutes ago before this detour?"** at the moment of the detour, plus a one-key way
to capture "I saw a thing, I intend to act on it" before working memory drops it. 0.3.0
**adds** a global-hotkey overlay, a where-was-I / mark-this-moment workflow, and an opt-in
localhost API with an MCP wrapper.

The theme: **every removal deletes a decision; every addition reuses infrastructure that
already exists** (the store, hybrid search, the sidecar, the capture pipeline). No new
subsystem is invented in this arc.

## Scope

**Ships in 0.3.0** (build order): PR1 (specs contract) → PR2 (trigger trim) → PR3 (Beta
tier removal) → PR4 (image-embedding lane removal) → PR5 (Flow overlay) → PR6 (where-was-I
+ marks) → PR7 (local API + export) → PR8 (MCP server) → PR9 (integration audit + release).

PR2–PR4 (the subtractions) are **independent of each other and of PR5–PR8**; they may land
in any order but are sequenced first so the audit and every new feature build on the
smaller surface. PR5 is a prerequisite for the overlay half of PR6. PR7 is a prerequisite
for PR8.

**Deferred (recorded in `07` during PR1, not built in this arc):**
- **Audio capture / transcription** — the single most-requested capability in this product
  category, and explicitly out: mic capture, a Whisper lane, and consent UX are a full arc
  of their own. Revisit for 0.4.x.
- **Custom GGUF path** ("bring your own model") — the escape hatch that replaces the Beta
  tier for tinkerers. Small, but out of 0.3.0 to keep PR3 a pure subtraction.
- **Proactive nudges** ("you've been on X for 40 min…") — deliberately out. 0.3.0's
  where-was-I surface is **pull-based only** (user invokes it); no notifications, no
  shame-analytics. Any push mechanism is a separate, opt-in design conversation.
- **Marks in Recall reports** — reports stay as shipped in 0.2.x; surfacing unresolved
  marks inside daily/weekly reports is a later refinement.
- **API write scopes beyond marks** — v1 of the API is read-only except `POST /v1/marks`.

**Assumptions:** single-user; the 0.2.x line is tagged and its build-loop entries archived
per `04 §7` before PR1 branches. Existing databases are supported — 0.3.0 migrations are
forward-only and **destroy only derived, re-derivable data** (image-embedding vectors and
dead jobs); frames, images, text, and text embeddings are never touched.

## Part I — Subtraction (PR2–PR4)

### PR 2 — Event-trigger trim: keep foreground + idle, delete the rest

**Goal:** reduce the six event-capture triggers to the two that carry the value and cost
the least, and delete the `WH_MOUSE_LL` global mouse hook entirely.

**What goes:**
- **click** and **scroll-stop** (`capture.event_on_click` / `capture.event_on_scroll_stop`)
  — these are the only consumers of the global low-level mouse hook
  (`SetWindowsHookExW(WH_MOUSE_LL, …)` in `crates/capture/src/events.rs`). The 0.2.0
  roadmap deliberately steered away from `WH_MOUSE_LL` (input latency + invasiveness); it
  was added at explicit user request (`06`, `07` #47) and is now retired by the same user.
  Deleting them removes the mouse hook, `mouse_proc`, `MOUSE_FLAGS`, and the associated
  teardown branches — a whole `unsafe` path gone.
- **clipboard** (`capture.event_on_clipboard`, `AddClipboardFormatListener`) — contents
  were never read, but a clipboard listener is a privacy-optics landmine in any audit of a
  privacy-first product, and foreground-change fires at nearly all the same moments (users
  switch windows around copy/paste).
- **typing-pause** (`capture.event_on_typing_pause`) — redundant with **idle**: both are
  derived from the same `GetLastInputInfo` poll, differing only in threshold. One quiet-
  period trigger with one threshold is enough.

**What stays:** **foreground-change** (`SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`,
out-of-context — the highest-signal trigger), **idle**, the **fallback interval**, the
**debounce**, and the **min-interval rate ceiling**. Event mode remains opt-in, default
OFF. Timer mode is untouched.

**Mechanics:**
- `crates/capture/src/trigger.rs`: remove `InputEventKind::{Clipboard, Click, Scroll}`,
  the typing-pause edge, and their `TriggerConfig` fields; keep the pure state machine and
  its tests for the surviving paths.
- `crates/capture/src/events.rs`: the hook thread now installs only the foreground
  WinEvent hook; delete clipboard-listener and mouse-hook setup/teardown.
- `crates/traits`: remove the five retired `capture_event_*` settings fields
  (`on_clipboard`, `on_typing_pause`, `on_click`, `on_scroll_stop`, `typing_pause_ms`);
  settings **load** tolerates and drops unknown keys (log once, no error).
- **No schema change.** `frames.capture_trigger` keeps its widened `CHECK`; legacy
  `clipboard` / `typing_pause` / `click` / `scroll_stop` tokens remain readable and the
  Moment view's "Captured via" row keeps rendering them. New frames simply never carry
  the retired tokens again.
- Settings UI: the event-capture section shrinks to master toggle + foreground + idle +
  the three surviving thresholds.

**Acceptance:** `WH_MOUSE_LL`, `AddClipboardFormatListener`, and `typing_pause` appear
nowhere in the tree (except CHANGELOG/specs history and the `CHECK` constraint); event
mode live-verified firing on alt-tab and on idle; a legacy frame with `capture_trigger =
'click'` still renders in Moment; full verification suite green.

### PR 3 — Model tiers: Default + Quality only (Beta retired)

**Goal:** cut the model-testing matrix by a third and make the licensing story uniformly
Apache-2.0 (MIT app + Apache models).

**What goes:**
- Vision Beta: `jc-builds/Qwen3.5-9B-VLM-Q4_K_M-GGUF`.
- Answer Beta: `nvidia/NVIDIA-Nemotron-3-Nano-4B-GGUF` — the only non-Apache license
  (NVIDIA OML) in the registry and the only hybrid Mamba-Transformer arch, i.e. the single
  riskiest row in `MODEL_REGISTRY.md` and the subject of its own risk row in `02 §6`.

**Mechanics:**
- `specs/MODEL_REGISTRY.md`: delete both Beta rows and the Nemotron invariants in §5;
  §4's resolve-at-download-time guidance is unchanged.
- Tier enum / registry code in `crates/inference` (and its `ts-rs`-generated UI type):
  two variants. Settings **load** maps a persisted `beta` selection to **`quality`** for
  that lane, logs it once, and persists the mapping.
- Settings UI: the tier picker shows two options per lane.
- `02 §2` ("3-tier per lane") and the `02 §6` Nemotron risk row updated by PR1;
  `README.md` model table updated in this PR.
- If any Beta GGUF is already on disk, leave it (models live outside the DB; users can
  delete via the existing model-management surface). Do **not** add cleanup logic.

**Acceptance:** grep for `Nemotron` / `Qwen3.5-9B` finds only history docs; a settings
file persisted with `beta` loads cleanly as `quality`; both remaining tiers of both lanes
still download/resolve per `MODEL_REGISTRY §4`; full verification suite green.

### PR 4 — Image-embedding lane removal (and the reranker flag with it)

**Goal:** delete the dark-launched, flag-off nomic-embed-vision lane. Text embeddings +
vision tags already cover semantic reach; a flag-off feature is pure carrying cost (a
second vec0 table, a second model download, code that rots untested). Git remembers it if
it's ever wanted back.

**What goes:**
- `enrich.image_embeddings` setting; the `with_image` path, image `Arc<Mutex<…>>` lane,
  and `IMAGE_MODEL_NAME` in `crates/embeddings`; `JobKind::EmbedImage` and its worker-pool
  arm and throttle references (the throttle's deepest level still floors `embed_text`);
  any image-vector arm in hybrid search; the `MODEL_REGISTRY §3` image row.
- The **reranker** feature flag noted in `00 §D` — never implemented; PR1 strikes it from
  the intake feature-flag list so the specs reflect reality.

**Migration (forward-only, `schema_version` +1):**
- `DROP TABLE image_embedding_vectors; DROP TABLE image_embeddings;` (the `AFTER DELETE`
  trigger goes with its table). This destroys **derived vectors only** — frames, stored
  images, text, and text embeddings are untouched, and the data is re-derivable in
  principle from stored frames.
- `DELETE FROM jobs WHERE kind = 'embed_image';` (any state — the kind no longer exists).
- Migration is proven by a populated-DB migration test (the 0.2.1 `frames`-rebuild test is
  the pattern).

**Acceptance:** `nomic`, `image_embedding`, `EmbedImage` appear nowhere outside history;
fresh-DB schema and migrated-DB schema agree; hybrid search results unchanged on the
10k-frame fixture (image arm was flag-off, so parity is expected and must be shown); full
verification suite green.

## Part II — Flow recall (PR5–PR6)

### PR 5 — The Flow overlay (global-hotkey instant search + ask)

**Goal:** recall without switching context. A system-wide hotkey summons a lightweight
always-on-top overlay over whatever the user is doing; search-as-you-type over content
text; `Esc` dismisses; `Enter` jumps to the Moment in the main window. This is the
single biggest friction-killer in the product, and friction is the difference between a
tool an ADHD user has and a tool an ADHD user *uses*.

**Mechanics:**
- **Hotkey:** `tauri-plugin-global-shortcut` (Tauri 2, official plugin). Default
  **`Ctrl+Alt+Space`** (`Alt+Space` collides with the Windows system menu and PowerToys
  Run; `Win+…` combos are OS-reserved minefields). Configurable in Settings; a failed
  registration (conflict with another app) surfaces as a visible Settings warning + toast,
  never a silent no-op.
- **Window:** a second, pre-created Tauri window — frameless, transparent background,
  always-on-top, skip-taskbar, centered upper-third, **hidden not destroyed** (show/hide,
  so summon latency is window-show latency, not webview boot). Hide on `Esc` and on blur.
- **Behavior:** input focused on show; debounced search-as-you-type calling the existing
  hybrid-search IPC (content text default; no new retrieval code); top N results with
  thumbnails; `Enter` shows the main window on the Moment; `↑/↓` navigate. A mode toggle
  (`Tab` or a `?` prefix) switches to **Ask**, streaming a grounded answer with cited
  frames via the existing ask pipeline. Opened with an empty query, the overlay shows the
  **where-was-I strip** (PR6) instead of results.
- **Privacy:** the overlay is the app's own window, so the existing self-exclude capture
  gate must cover it — extend the privacy-gate tests to assert the second window is never
  captured.
- **Perf bars:** overlay visible **< 150 ms** from hotkey (measured warm); first results
  within the existing **< 200 ms** search budget.
- **UI contract:** `UI_REFERENCE.md` gains an Overlay screen spec — identity (it must
  read as ScreenSearch: Scanline-Timeline signature, one-accent discipline, tokens only),
  all five view states, keyboard operation, reduced-motion. Written by PR1, implemented
  here.

**Acceptance:** hotkey works while an unrelated app is fullscreen-focused; latency bars
met and shown with measurements; overlay never appears in its own capture history after a
live capture session; conflict path demonstrated (register a colliding hotkey, see the
warning); full verification suite green.

### PR 6 — "Where was I?" + Mark-this-moment

**Goal:** the ADHD core of the arc. One key answers *"what was I doing before this
detour?"*; another key externalizes *"I saw something, I intend to act on it."* Both are
pull-based; neither notifies, nags, or scores the user.

**Where-was-I (context resume):**
- A pure, unit-tested heuristic (a store query + a small pure function; no new crate):
  the **last sustained context** = the most recent run of frames, ending before the
  current foreground app's session began, in which the same context key persisted for at
  least `resume.min_dwell_secs` (default **120**, a setting like every 0.2.x threshold).
  Context key = `app_hint`, refined by browser domain (from `browser_url`) when present.
  Excluded from candidacy: the current foreground app, ScreenSearch itself, and apps on
  the existing excluded-apps list.
- Returns the run's representative (last) frame + app, window title, URL, span start/end.
- Exposed as an IPC command (`where_was_i`); surfaced in the **overlay's empty state**
  (PR5) and as a **Deck card** ("Jump back: *repo — VS Code*, until 14:32"). `Enter` /
  click opens the Moment; from there the existing frame context gets the user back.

**Mark-this-moment (intention capture):**
- Second global hotkey, default **`Ctrl+Alt+M`**, same registration/conflict handling as
  PR5. On press: capture **now** (a new `capture_now` request into the capture worker that
  **bypasses the diff gate** for this one frame — a demanded frame must never be dropped
  as "unchanged"), insert the frame, and insert a **mark**. A brief, quiet overlay toast
  confirms ("Marked ✓ — note?"), with an optional one-line note; ignoring it costs nothing.
- **Schema (`schema_version` +1, may share PR4's bump if sequenced together — they don't;
  each PR bumps once):**
  `marks(id INTEGER PRIMARY KEY, frame_id INTEGER NOT NULL REFERENCES frames(id) ON
  DELETE CASCADE, created_at INTEGER NOT NULL, note TEXT, resolved_at INTEGER)` — the
  CASCADE convention of every per-frame table. A retention wrinkle, decided now: marked
  frames' **images** still expire per retention like any other frame (the mark keeps the
  text reconstruction reachable); an unresolved mark never blocks retention.
- **Deck "Intentions" strip:** unresolved marks, newest first — thumbnail (or
  reconstruction), note, age; actions: open Moment, resolve, dismiss (resolve with no
  action). No badge counts anywhere else in the app.

**Acceptance:** where-was-i returns the correct run on a scripted fixture (unit) and on a
live session (alt-tab from work app → browser detour → hotkey → the work app's context is
offered); a mark created from a fullscreen third-party app lands with a frame captured at
press time even when the screen was static (diff-gate bypass demonstrated); marks strip
live-verified; full verification suite green.

## Part III — Open surface (PR7–PR8)

### PR 7 — Local HTTP API + export (opt-in, localhost, token)

**Goal:** turn the app into a platform without moving a byte off the machine. This is the
open-source audience's loudest ask, and it lets the ADHD workflow escape the silo (marks
→ real todo systems; screen history → Obsidian, scripts, agents).

**Posture (spec'd explicitly by PR1 in `03`):** default **OFF**. When enabled: binds
**`127.0.0.1` only, hard-coded** (not a setting); every request requires a **bearer
token** generated on first enable, stored in settings, shown/copyable/regenerable in
Settings. The threat model is stated plainly in the spec and the Settings UI: *any local
process holding the token can read your entire screen history* — enabling this is an
explicit trust decision.

**Mechanics:**
- New crate `crates/api` (axum; reqwest/rustls are already in-tree, axum is the one new
  dependency), behind a trait, wired in the composition root, **not constructed at all**
  unless enabled. Default port **43210**, configurable.
- **Endpoints (v1):**
  - `GET /v1/health` — version, uptime, capture state.
  - `GET /v1/search?q=&from=&to=&limit=&include_chrome=` — existing hybrid search,
    content-text default, same semantics as the UI.
  - `POST /v1/ask` — grounded answer, **SSE stream**, cited frame ids (the existing ask
    pipeline; the sidecar client already speaks SSE).
  - `GET /v1/frames/{id}` — metadata + text; `?image=1` returns the stored WebP.
  - `GET /v1/context/where-was-i` — PR6's heuristic.
  - `GET /v1/marks` · `POST /v1/marks` (frame_id or "now") · `POST /v1/marks/{id}/resolve`
    — the only write surface.
  - `GET /v1/export?from=&to=&format=json` — frames + content text (+ marks), **no
    images** in v1 export. A Settings "Export…" button calls the same code path
    internally, so export works even with the API disabled.
- OpenAPI-lite documentation: a hand-written `docs/API.md` (v1 is small; no codegen).

**Acceptance:** API off by default (fresh profile: nothing listens); with API on, a
request without/with-wrong token gets 401; every endpoint exercised in an integration
test against a fixture DB; a bind attempt on `0.0.0.0` is impossible by construction
(shown in code review, asserted in a test); Settings export produces a valid JSON file
with the API disabled; full verification suite green.

### PR 8 — MCP server (`screensearch-mcp`)

**Goal:** meet the 2026 agent ecosystem where it is. A thin **stdio MCP server** that
wraps PR7's HTTP API, so Claude Desktop / Claude Code / any MCP client can search and ask
the user's screen history — locally.

**Mechanics:**
- New workspace binary crate `crates/mcp` → `screensearch-mcp.exe`, shipped in the NSIS
  installer alongside the app. **No store access, no app coupling** — it is purely an
  HTTP client of `127.0.0.1:<port>` with the bearer token, taken from args/env
  (`SCREENSEARCH_API_URL`, `SCREENSEARCH_API_TOKEN`). If the API is off, every tool call
  returns a clear "enable the API in ScreenSearch Settings" error.
- **Tools:** `search_screen_history`, `ask_screen_history`, `get_moment`,
  `where_was_i`, `list_marks`, `add_mark`.
- `docs/MCP.md`: the copy-paste config snippet for Claude Desktop / Claude Code, plus the
  same threat-model paragraph as PR7.

**Acceptance:** the binary speaks MCP handshake + tool listing over stdio; each tool
round-trips against a live app instance with the API enabled; the API-off error path is
clean; installer includes the binary; full verification suite green.

## Pre-answered product decisions (do not re-ask; do not re-litigate)

So stop-at-ambiguity fires on *new* ambiguity only, the following are **decided**:

| # | Decision |
|---|---|
| D1 | Surviving event triggers: **foreground + idle** (+ fallback interval, debounce, min-interval). Clipboard, typing-pause, click, scroll-stop are removed, not hidden. |
| D2 | No schema change for retired trigger tokens; legacy tokens stay readable. |
| D3 | Persisted `beta` tier selections map to **`quality`** on load. |
| D4 | Beta GGUFs already on disk are left alone; no cleanup logic. |
| D5 | PR4's migration **drops** `image_embeddings` / `image_embedding_vectors` and deletes `embed_image` jobs. Derived data only; acceptable by design. |
| D6 | Default hotkeys: overlay **`Ctrl+Alt+Space`**, mark **`Ctrl+Alt+M`**; both configurable; registration failure is a visible warning, never silent. |
| D7 | The overlay window is hidden-not-destroyed, and must be covered by the self-exclude capture gate (tested). |
| D8 | `capture_now` (marks) bypasses the diff gate for that single frame. |
| D9 | Where-was-I default `resume.min_dwell_secs` = **120**; context key = `app_hint` refined by browser domain; excluded apps and self never qualify. |
| D10 | Marked frames follow normal retention (images expire; the mark keeps the reconstruction reachable). No retention pinning in 0.3.0. |
| D11 | API: default OFF; `127.0.0.1` hard-coded; bearer token mandatory; default port **43210** (configurable). |
| D12 | Export v1 = JSON, frames + content text + marks, **no images**. |
| D13 | MCP server is a separate stdio binary wrapping the HTTP API — it never links the store. |
| D14 | No proactive notifications/nudges anywhere in this arc. Pull-based surfaces only. |
| D15 | Each PR that changes schema bumps `schema_version` by exactly one, with a populated-DB migration test. |

## Risks

| Risk | Mitigation |
|---|---|
| Global hotkey conflicts (PowerToys, IMEs, games) | Non-default combos chosen; configurable; registration failure is loud (Settings warning + toast). |
| Users relying on a removed trigger / tier / lane | Release notes lead with removals + rationale; settings load is tolerant (drop + log, never crash). |
| Overlay focus/fullscreen edge cases (games, exclusive fullscreen) | Accept imperfection: document that exclusive-fullscreen may suppress the overlay; never steal focus without the hotkey. |
| API token leakage → full-history read by local malware | Off by default; localhost-only; plain-language threat model in Settings and docs; regenerate button. |
| `capture_now` racing the capture worker | It's a request into the existing worker channel, serialized like any capture cycle; diff-gate bypass is a per-request flag, not a mode. |
| axum dependency growth | One crate, feature-trimmed, only compiled into the app (MCP binary uses reqwest only). |
| Scope creep via "while we're in there" | The deferred list above is the pressure valve — new wants go to `07`, not into this arc. |
